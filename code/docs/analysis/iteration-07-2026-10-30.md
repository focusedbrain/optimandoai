# Iteration 07 — 2026-10-30

This iteration continues from `docs/analysis/iteration-06-2026-09-26.md`. It is the "egress stop": the Phase 0 corrective items through which data reaches a cloud model against the product's own governance (0.13–0.16), the silent image drop (0.24) and the letter field-value log (0.4). The code tip is `b1abbb4e` on `integration/consolidated-current`.

## Decision taken

**D-37, egress policy:** the recommended option. Local first; a remote model receives data only through an egress check; a stored API key is not consent; captures stay local. One consequence: cloud inbox AI now needs an explicit `preference: 'cloud'`, and no product surface sets one today, so inbox AI is effectively local until such a setting exists.

## Finding: qBEAP preview never updated on P2P-inline ingest

`beapEmailIngestion.ts` declared `const preview` and reassigned it after a successful qBEAP decrypt (since `6eecab0a`, 2026-05-22). esbuild compiles that to a runtime `TypeError`, which the surrounding `catch` turned into `depackageError = "qBEAP decrypt error: Assignment to constant variable."`. The row was still written, because `canonicalJson` was already set, but the inbox preview kept the encrypted placeholder and the Sandbox-clone lead-in was not stripped. The same line was TS2588 in the typecheck baseline. The vite build prints it as a warning ("This assignment will throw").
