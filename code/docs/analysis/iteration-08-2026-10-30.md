# Iteration 08 — 2026-10-30

This iteration continues from `docs/analysis/iteration-07-2026-10-30.md`. It repairs the sandbox mail path: a host paired with a sandbox fetches no mail itself, and since build036 (`73315416`, 2026-07-10) the sandbox had no transport to deliver what it fetched. The code tip is `9c0c6b63` on `integration/consolidated-current`.

## Findings that started this iteration

- **The sandbox → host return path was dead.** Schema v71 retired the direct-LAN `/beap/ingest` listener, and `RETIRE_DIRECT_SANDBOX_DELIVERY` blocks the only delivery transport (`critical-jobs/remote/sandboxEmailDelivery.ts`). The sealed `ingestion_poll_result` carries counts only. With the sandbox online, every fetched message was unpacked and then held on the sandbox.
- **Silent failure.** The sandbox still reported `status: ok`, and the host showed "Sandbox ingestion poll triggered … Fetched 5, delivered 0, held 5" as a green sync. Any unknown poll status (`held_no_custody_key`, `not_owner`, passed-through error codes) also showed as success.
- **No mail loss.** The sandbox keeps no cursor: each poll lists the newest 20 messages, so held messages are fetched again. Messages beyond that window are never fetched.
- **The relay only accepts `sealed_service_rpc_v1` from sandbox devices** (`packages/coordination-service/src/server.ts`, sandbox egress guard). A delivery as a native qBEAP message package would be refused, so delivery uses the sealed service-RPC envelope.
- **Configuration on the test host.** `p2p_config` pointed at a local test relay (`ws://192.168.178.28:51249`) left by `pnpm session:start`; nothing listened there, so every trigger failed with `E_INGESTION_POLL_LINK_DOWN`. The host was switched back to `https://relay.optirando.com` with `scripts/session/configure-coordination-worker.cjs` (not a code change).

## Decisions taken

- **D-38, the relay carries more than `p2p_signal`:** it stays blind (routing metadata and ciphertext only) and carries `p2p_signal`, sealed service RPC (Host AI inference without a DataChannel, ingestion poll trigger/result, sandbox → host mail delivery) and handshake capsules. Recorded in `.cursor/rules/internal-inference-p2p-invariants.mdc`.
- **Order:** the sandbox path first (this iteration); the local isolated executor for single-machine ingestion (stage 1) afterwards, because the seam path today needs a paired sandbox's custody key and has no readable attachments or attachment text.

## What changed (`9c0c6b63`)

| Area | Change |
|---|---|
| Honest status | `sandboxIngestion.ts` reports `held_delivery_failed` (unpacked > delivered) and `held_depackage_failed` (fetched > delivered) instead of `ok`. `effectiveIngestionPollStatus` on the host applies the same rule to the counters, whatever the sandbox sends; any other non-ok status is a named failure (`TRIGGER_NOT_COMPLETED_HINT`). New `IngestionStatusCode` `PAUSED_DELIVERY_FAILED`, a red banner (`IngestionStatusBanner`) and an extension explainer scenario. |
| 0.26, authenticated envelope | `sealedServiceRpc.ts` schema_version 2: the key mixes DH(ephemeral, recipient) and DH(sender static, recipient), so only the holder of the device key pinned on the handshake can produce an envelope the receiver opens. `expires_at` and `message_id` are bound in the AAD; open refuses expired and too-far-future envelopes (24 h cap); the handler that takes a message claims its id once (`claimSealedServiceRpcMessage`). Opening is stateless because the dispatch chain opens one envelope in several handlers to route by inner type. |
| Relay paths | Every relay sender seals v2 (`relaySend.sealServiceRpcForRelay` is async and authenticated; poll result, Host AI request/result senders). Every relay receiver opens with `requireAuthenticated` (v1 refused). v1 stays only for the in-capsule `context_blocks_sealed` canonical form (`contextSyncSeal.ts`, `canonicalRebuild.ts`). The relay capsule carries and parses the v2 fields. |
| Delivery | New `email/sandboxDelivery/relayDelivery.ts` (sandbox: seal + send `sandbox_email_delivery`, delivery ledger, receipt handler) and `relayDeliveryHostHandler.ts` (host: pair-role check, account mapping by mailbox address then trigger account, dedupe per account + provider message id, write via the existing host writer, sealed receipt `stored`/`duplicate`/`failed`). Custody-sealed originals stay on the sandbox. 24 h relay lifetime, 6 MB plaintext cap (`too_large_for_relay`). Unacknowledged or failed deliveries are resent after 30 minutes; acknowledged ones are skipped. |
| Egress policy | `sandbox_email_delivery` may leave the sandbox inside a sealed envelope; `sandbox_email_delivery_ack` may reach it. |

**Compatibility:** both devices need this build. A peer on an older build cannot open v2 envelopes; the host then reports "Sandbox unreachable" after the trigger timeout, not a version mismatch.

- The replay guard is in memory: after a restart an envelope can be opened once more within its own lifetime.
